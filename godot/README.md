# 雾屿 · Godot 主工程

Godot 4.7.2，GDScript，Compatibility，固定正交相机。四关均已迁入，运行时不依赖原版 Three.js。Web 使用单线程导出，直接部署 GitHub Pages。

## 工程结构

- `scenes/game.tscn` / `scripts/game.gd`：共用入口，输入、角色行走、机关吸附、连续碰撞、取景、目录、教学、音效与通关切换。
- `scenes/folded_frame.tscn`、`double_cloister.tscn`、`blue_gate.tscn`、`hanging_stair.tscn`：四关原生建筑场景，机关和旋钮独立。
- `scenes/traveller.tscn`：银发黄衣角色，Body、LeftLeg、RightLeg 独立动画；原版尺寸，移速 2.175 单位/秒。
- `data/levels.json` 与四关 JSON：道路图、接口姿态、真实碰撞边界、取景与显示深度。
- `scripts/navigation.gd`：道路图寻路、中途停止、反向移动和平台搭乘；指定姿态及投影成立时才连通错觉接口。
- `scripts/progress.gd`：选择关卡、完成记录和声音设置；`user://progress.json`，Web 通过 IndexedDB 持久化。
- `scripts/optics.gd` 和空间着色器：整块建筑沿视线调整显示深度；人物跟随脚下道路；原始自身深度子视口抑制内部面。
- `web/shell.html`：柔和背景的中文加载页、进度与失败重试。
- `assets/`：图标、采样音效、Noto Sans SC 字体子集及 OFL 许可。

模型和道路分别维护；修改模型需同步道路与错觉接口，普通导航网格无法替代明确设计的不可能空间连接。`bake` 会覆盖生成场景的手工编辑，正常构建不执行它。

## 四关规则

1. **折臂**：绕 X 轴翻转。C 横段在 B 后，C 左侧短臂在 B 前；C 前段使用完整 C 的原始深度纹理保持转角连续。点击与渲染共用遮挡优先级，不能靠角度阈值跳层。
2. **双廊**：绕 Y 轴旋转双层紫色横梁。下层经右侧错层回廊到上层，站上梁再转动，连接终点。
3. **门阶**：初始放平，过前桥与阶梯；第一次立柱，通过柱顶两段路径跨过方形缺口；进入白廊后第二次放平，沿后桥抵达终点。终点保持在后侧蓝柱后方。
4. **悬阶**：绕 Y 轴旋转悬臂。登下层梁，转至 270° 接浮空折角平台，再登上层梁、转至 90° 抵达终点。

第一关保留原版人物优先层；后三关人物接受真实建筑遮挡。第一关人物与细支柱的局部遮挡仍待完善，不要把人物优先层扩展到其他关。

旋钮方向同时考虑机关世界转轴、旋转符号和安装面。真实定向包围盒逐步检查运动，视觉接头的微小延伸保持原版碰撞边界。统一贴地金色四瓣终点。

Compatibility 的 RGB 深度纹理输出需偏置到 UNORM8 字节格内，防止高位字节向下舍入导致缺面。MSAA 容差随表面梯度变化；Godot 反向深度使用 [0,1]，特殊绘制层应留在合法区间，避免角色与旋钮裁切。

## 验证

仓库根目录执行 `./tools/godot.ps1 verify`、`capture`、`playthrough`。截图存入忽略目录 `artifacts/godot-captures/`。

`verify` 检查四关解法、门阶柱顶必须经过及无单姿态捷径、964 个碰撞姿态、完整双向运动、中途反走和旋钮方向。`playthrough` 使用真实游戏行走与转动流程逐关通关并截图，直接驱动游戏逻辑，不代替浏览器鼠标测试。`capture` 检查中间姿态。

`npm test` 保留原版 36 个参考测试，验证迁移源数据的模型、接缝、路径和遮挡约定。Godot 原生与网页还需检查完整路宽、正反向旋转、人物搭乘和点击一致性。

网页构建：`npm run build`，预览：`npm run dev`，地址 `http://127.0.0.1:5180/`。默认 WASM 未压缩约 39.5 MB，首屏下载大于原版；尚未覆盖所有真实手机与 Safari 浏览器。以后可编译裁减功能的模板降低体积。
